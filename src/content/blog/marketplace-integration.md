## Marketplace Integration คืออะไร

**Marketplace Integration** คือการเชื่อมต่อแพลตฟอร์ม Marketplace (Shopee, TikTok Shop, Lazada) เข้ากับระบบ backend ของธุรกิจ เช่น ERP หรือ Business Automation Platform ผ่าน API เพื่อให้ข้อมูลไหลสองทิศทางโดยอัตโนมัติ โดยไม่ต้องเข้า Seller Center แต่ละช่องทางและคีย์ข้อมูลด้วยมือ

ก่อนมี Integration ทีมงานต้อง:
1. เข้า Shopee Seller Center ดูออเดอร์
2. เข้า TikTok Shop Seller Center ดูออเดอร์
3. เข้า Lazada Seller Center ดูออเดอร์
4. คีย์ออเดอร์ทั้งหมดลง Excel หรือ ERP
5. อัปเดตสต๊อกกลับไปแต่ละช่องทางด้วยมือ
6. พิมพ์ใบปะหน้าจากแต่ละ Seller Center
7. อัปเดต Tracking Number กลับไปทีละออเดอร์

หลังมี Integration ทุกอย่างเกิดอัตโนมัติ ออเดอร์ไหลเข้า ERP สต๊อกซิงค์ข้ามช่องทาง ใบปะหน้าพิมพ์จาก ERP และ Tracking Number อัปเดตกลับไป Marketplace โดยไม่ต้องคีย์อะไรเลย

### ความแตกต่างระหว่าง "เชื่อม" กับ "ไม่เชื่อม"

| เกณฑ์ | ไม่มี Integration | มี Integration |
|------|-------------------|----------------|
| ดูออเดอร์ | เข้า 3 Seller Center | เห็นใน ERP หน้าเดียว |
| อัปเดตสต๊อก | คีย์มือ 3 ระบบ | ซิงค์อัตโนมัติ |
| ใบปะหน้า | พิมพ์จาก 3 ที่ | พิมพ์จาก ERP |
| Tracking | อัปเดตทีละออเดอร์ | อัปเดตอัตโนมัติ |
| ข้อมูลลูกค้า | ไม่เก็บ | เข้า CRM อัตโนมัติ |
| เวลา/วัน | 4-6 ชั่วโมง | 30 นาที |
| ความผิดพลาด | สูง | ต่ำมาก |

> 💡 **Tip:** ถ้าร้านค้าของคุณมีออเดอร์รวม 50 ออเดอร์ต่อวันขึ้นไป จาก 2 ช่องทางขึ้นไป Marketplace Integration ไม่ใช่ "น่ามี" แต่เป็น "ต้องมี" การคีย์มือจะไม่ Scale ได้อีก

## ทำไมต้องเชื่อม Marketplace เข้ากับ ERP

### พฤติกรรมผู้บริโภคเปลี่ยน

ลูกค้าไทยช้อนข้ามช่องทาง คนเดียวซื้อทั้ง Shopee TikTok Shop และ Lazada ร้านค้าต้องอยู่ในทุกช่องทาง แต่การจัดการแยกกันทำให้ทีมงานเหนื่อนและเกิดความผิดพลาด

### ความเร็วคือคีย์

ลูกค้าคาดหวังให้จัดส่งเร็ว ถ้าร้านค้าใช้เวลา 1-2 วันแค่รวมออเดอร์ คู่แข่งที่มี Integration จัดส่งในวันเดียว ลูกค้าเลือกคู่แข่ง

### ความผิดพลาดทำลาย Rating

สต๊อกไม่ตรง ขายของที่หมด โดนยกเลิกออเดอร์ โดน Penalty จาก Marketplace Rating ตก อันดับร้านค้าตก ยอดขายลด วงจรเลวร้าย

### ข้อมูลลูกค้าหาย

เมื่อลูกค้าซื้อบน Marketplace ข้อมูลอยู่ใน Seller Center ถ้าไม่ดึงเข้า CRM ธุรกิจไม่รู้ว่าลูกค้าคนไหนซื้ออะไร ไม่สามารถติดตามหรือส่งโปรโมชั่นได้

> ⚠️ **Callout:** ร้านค้าที่มี Marketplace Integration ลดเวลาจัดการออเดอร์ 80% ลดความผิดพลาด 95% และเพิ่มความเร็วในการจัดส่ง 40% เมื่อเทียบกับร้านค้าที่คีย์มือ

### ทิศทางของข้อมูล

```
Marketplace ──────► ERP        (ดึงออเดอร์, ข้อมูลลูกค้า)
ERP ──────► Marketplace        (อัปเดตสต๊อก, Tracking, ราคา)
ERP ◄──────► Marketplace       (ซิงค์สองทิศทาง Real-time)
```

### ช่องทางการเชื่อมต่อ

**1. Official API** — แต่ละ Marketplace มี API อย่างเป็นทางการ:
- Shopee Open Platform API
- TikTok Shop API
- Lazada Open Platform API

**2. Webhook** — Marketplace ส่ง Event ไป ERP เมื่อมีออเดอร์ใหม่ สต๊อกเปลี่ยน หรือสถานะเปลี่ยน

**3. REST API (ERP side)** — ERP มี API สำหรับรับข้อมูลจาก Marketplace และส่งข้อมูลกลับ

> 💡 **Tip:** การเชื่อมผ่าน Official API ปลอดภัยที่สุด เพราะได้รับการรองรับจาก Marketplace ไม่มีความเสี่ยงถูกแบน แต่ต้องสมัครเป็น Developer และผ่านการอนุมัติ ใช้เวลา 1-7 วัน

## Order Sync ดึงออเดอร์อัตโนมัติ

**Order Sync** คือการดึงออเดอร์จาก Marketplace เข้าสู่ ERP อัตโนมัติ ทีมงานเห็นออเดอร์จากทุกช่องทางในหน้าจอเดียว ไม่ต้องเข้า Seller Center แต่ละช่องทาง

### วิธีการทำงาน

```
ลูกค้าสั่งซื้อบน Shopee
        │
        ▼
Shopee ส่ง Webhook ไป ERP ──── "ออเดอร์ใหม่ #12345"
        │
        ▼
ERP ดึงรายละเอียดออเดอร์ผ่าน API
        │
        ├── เลขออเดอร์
        ├── ชื่อและที่อยู่ลูกค้า
        ├── รายการสินค้า
        ├── จำนวนและราคา
        ├── ช่องทางชำระเงิน
        └── สถานะการชำระ
        │
        ▼
ERP สร้างออเดอร์ในระบบ
        │
        ├── บันทึกใน Order Module
        ├── ส่งข้อมูลลูกค้าไป CRM
        ├── แจ้งเตือนทีมคลัง
        └── อัปเดต Dashboard
```

### สถานะออเดอร์ที่ต้องซิงค์

| สถานะ | ความหมาย | ERP ทำอะไร |
|-------|---------|------------|
| Unpaid | รอชำระเงิน | บันทึกออเดอร์ รอ |
| Paid | ชำระแล้ว | แจ้งทีมคลังเตรียมของ |
| Processing | กำลังจัด | อัปเดตสถานะใน ERP |
| Shipped | จัดส่งแล้ว | อัปเดต Tracking |
| Completed | ลูกค้ารับแล้ว | บันทึกยอดขาย |
| Cancelled | ยกเลิก | คืนสต๊อก |
| Returned | คืนสินค้า | รับคืนเข้าคลัง |

### ความถี่ในการซิงค์

- **Real-time (Webhook)** — เมื่อมีออเดอร์ใหม่ Marketplace ส่ง Webhook ทันที ERP ดึงข้อมูลภายใน 2-5 วินาที
- **Polling (ทุก 5-15 นาที)** — ERP ดึงออเดอร์ใหม่ทุก 5-15 นาที เหมาะสำหรับระบบที่ไม่รองรับ Webhook
- **Manual** — กดดึงเอง เหมาะสำหรับทดสอบ ไม่แนะนำสำหรับใช้จริง

> 💡 **Tip:** เลือกระบบที่รองรับ Webhook เพราะ Real-time ทำให้ทีมคลังเริ่มจัดสินค้าได้ทันทีที่ลูกค้าสั่ง ไม่ต้องรอ Polling รอบถัดไป ความเร็วในการจัดส่งเพิ่มขึ้นอย่างชัดเจน

## Inventory Sync ซิงค์สต๊อกข้ามช่องทาง

**Inventory Sync** คือการอัปเดตสต๊อกสินค้าข้ามช่องทางแบบ Real-time เมื่อมีออเดอร์ในช่องทางหนึ่ง สต๊อกในทุกช่องทางลดลงทันที ป้องกันการขายสินค้าที่หมดสต๊อก

### วิธีการทำงาน

```
สินค้า A มีสต๊อก 10 ชิ้น
        │
        ├── Shopee: 10 ชิ้น
        ├── TikTok Shop: 10 ชิ้น
        ├── Lazada: 10 ชิ้น
        └── ERP: 10 ชิ้น
        
ลูกค้าซื้อ 3 ชิ้นบน Shopee
        │
        ▼
ERP ลดสต๊อก เหลือ 7 ชิ้น
        │
        ├── API ──► Shopee: อัปเดตเป็น 7 ชิ้น
        ├── API ──► TikTok Shop: อัปเดตเป็น 7 ชิ้น
        └── API ──► Lazada: อัปเดตเป็น 7 ชิ้น
        
ทุกช่องทางเหลือ 7 ชิ้น (ภายใน 2-5 วินาที)
```

### ปัญหาที่ Inventory Sync แก้ได้

**ก่อนมี Inventory Sync:**
- สินค้า A มี 10 ชิ้น ขายบน 3 ช่องทาง
- ลูกค้าซื้อ 8 ชิ้นบน Shopee → Shopee เหลือ 2 ชิ้น
- แต่ TikTok Shop และ Lazada ยังแสดง 10 ชิ้น
- ลูกค้าซื้อ 5 ชิ้นบน TikTok Shop → รับออเดอร์ แต่ของมีแค่ 2 ชิ้น
- ต้องยกเลิก 3 ชิ้น → Rating ตก → โดน Penalty

**หลังมี Inventory Sync:**
- ลูกค้าซื้อ 8 ชิ้นบน Shopee → ทุกช่องทางอัปเดตเหลือ 2 ชิ้น
- ลูกค้าซื้อบน TikTok Shop เห็นสต๊อก 2 ชิ้น → ซื้อได้ไม่เกิน 2 ชิ้น
- ไม่มีการขายเกินสต๊อก → Rating ดี → อันดับร้านค้าดีขึ้น

### การตั้งค่า Buffer Stock

**Buffer Stock** คือการเก็บสต๊อกไว้บางส่วนไม่ขาย เพื่อป้องกันกรณีสต๊อกไม่ตรงเนื่องจากความหน่วงของ API

```
สต๊อกจริงในคลัง: 10 ชิ้น
Buffer Stock: 2 ชิ้น
สต๊อกที่ขายได้: 8 ชิ้น

→ Marketplace แสดง 8 ชิ้น (ไม่ใช่ 10)
→ ถ้าขายหมด 8 ชิ้น ยังเหลือ 2 ชิ้นในคลัง
→ ป้องกันการขายเกินจากความหน่วง API
```

### ตารางเปรียบเทียบความถี่ซิงค์สต๊อก

| ความถี่ | ความเสี่ยงขายเกิน | ความเร็ว | เหมาะกับ |
|---------|-------------------|---------|----------|
| Real-time (Webhook) | ต่ำสุด | 2-5 วินาที | ออเดอร์สูง |
| ทุก 5 นาที | ต่ำ | 5 นาที | ออเดอร์ปานกลาง |
| ทุก 15 นาที | ปานกลาง | 15 นาที | ออเดอร์น้อย |
| ทุก 1 ชั่วโมง | สูง | 1 ชั่วโมง | ไม่แนะนำ |
| มือ | สูงมาก | ไม่ Real-time | ไม่ควรใช้ |

> ⚠️ **Callout:** ถ้าขายสินค้าเดียวกันบน 3 ช่องทางและออเดอร์รวม 100+ ต่อวัน ความเสี่ยงขายเกินสต๊อกสูงมากถ้าซิงค์ด้วยมือ การใช้ Buffer Stock 2-3 ชิ้นร่วมกับ Real-time Sync ลดความเสี่ยงได้ 95%+

## Webhook การสื่อสารแบบ Real-time

**Webhook** คือกลไกที่ Marketplace ส่งข้อมูลไป ERP ทันทีเมื่อมี Event เกิดขึ้น ไม่ต้องรอให้ ERP มาดึง (Polling) เปรียบเหมือน Marketplace โทรบอก ERP ทันทีเมื่อมีออเดอร์ใหม่ แทนที่ ERP จะโทรถามทุก 5 นาที

### ภาพประกอบ Webhook vs Polling

```
─── Polling (ERP ถามทุก 5 นาที) ───

ERP: "มีออเดอร์ใหม่ไหม?"     → Shopee: "ไม่มี"
(5 นาทีให้หลัง)
ERP: "มีออเดอร์ใหม่ไหม?"     → Shopee: "ไม่มี"
(5 นาทีให้หลัง)
ERP: "มีออเดอร์ใหม่ไหม?"     → Shopee: "มี! ออเดอร์ #12345"
                             ← ERP ดึงข้อมูล

─── Webhook (Shopee บอกทันที) ───

ลูกค้าสั่งซื้อ
Shopee: "ออเดอร์ใหม่ #12345!" → ERP รับทันที
                                → ERP ดึงข้อมูล
                                → ทีมคลังเริ่มจัด
```

### Event ที่ Webhook ส่งได้

| Event | ความหมาย | ERP ทำอะไร |
|-------|---------|------------|
| Order Created | ออเดอร์ใหม่ | ดึงข้อมูลออเดอร์ |
| Order Status Changed | สถานะเปลี่ยน | อัปเดตใน ERP |
| Order Cancelled | ลูกค้ายกเลิก | คืนสต๊อก |
| Product Updated | ข้อมูลสินค้าเปลี่ยน | ซิงค์ข้อมูล |
| Stock Changed | สต๊อกเปลี่ยน | อัปเดตสต๊อก |
| Return Requested | ลูกค้าขอคืน | สร้างใบรับคืน |
| Tracking Updated | สถานะขนส่งเปลี่ยน | อัปเดตใน ERP |

### ข้อดีและข้อเสียของ Webhook

**ข้อดี:**
- Real-time ทันที ไม่ต้องรอ
- ประหยัด API Calls (ไม่ต้องดึงซ้ำ)
- ทีมคลังเริ่มจัดได้เร็วขึ้น
- สต๊อกซิงค์เร็วขึ้น

**ข้อเสีย:**
- ต้องมี Server ที่รับ Webhook ได้ (Public URL)
- ถ้า Server ล่ม Webhook หาย ต้องมีระบบ Polling สำรอง
- ต้องจัดการ Duplicate (Webhook ส่งซ้ำได้)
- บาง Marketplace ไม่รองรับ Webhook

> 💡 **Tip:** ระบบที่ดีควรใช้ Webhook เป็นหลักและ Polling เป็นสำรอง ถ้า Webhook หาย Polling จะดึงออเดอร์ที่หายไปในรอบถัดไป ทำให้ไม่มีออเดอร์หาย

## Shipping Integration จัดการขนส่ง

**Shipping Integration** คือการเชื่อมต่อกับบริษัทขนส่งและ Marketplace เพื่อจัดการใบปะหน้า การจัดส่ง และอัปเดต Tracking Number อัตโนมัติ

### วิธีการทำงาน

```
ERP จัดสินค้าเสร็จ
        │
        ▼
ERP สร้างใบปะหน้า (Shipping Label)
        │
        ├── ดึงที่อยู่ลูกค้าจากออเดอร์
        ├── เลือกขนส่ง (Kerry, Flash, Thailand Post)
        ├── สร้าง Tracking Number
        └── พิมพ์ใบปะหน้า
        │
        ▼
ทีมคลังติดใบปะหน้าและส่ง
        │
        ▼
ERP อัปเดต Tracking Number กลับไป Marketplace
        │
        ├── API ──► Shopee: "ออเดอร์ #12345 จัดส่งแล้ว Tracking: KRY123"
        ├── API ──► TikTok Shop: "ออเดอร์ #67890 จัดส่งแล้ว Tracking: KRY124"
        └── API ──► Lazada: "ออเดอร์ #54321 จัดส่งแล้ว Tracking: KRY125"
        │
        ▼
Marketplace แจ้งลูกค้า: "สินค้าจัดส่งแล้ว"
```

### ฟังก์ชันหลักของ Shipping Integration

**1. พิมพ์ใบปะหน้ารวม**
- พิมพ์ใบปะหน้าจากทุกช่องทางในที่เดียว
- รองรับกระดาษหลายขนาด (A4, A5, 70mm)
- พิมพ์เป็นชุด (Bulk Print) ได้

**2. เลือกขนส่งอัตโนมัติ**
- เลือกขนส่งที่ใกล้ลูกค้าที่สุด
- เลือกขนส่งที่ถูกที่สุด
- หรือตั้งกฎเอง เช่น "Shopee ใช้ Kerry, TikTok ใช้ Flash"

**3. อัปเดต Tracking อัตโนมัติ**
- ส่ง Tracking Number กลับไป Marketplace อัตโนมัติ
- ไม่ต้องคีย์ทีละออเดอร์
- อัปเดตทุกช่องทางพร้อมกัน

**4. ติดตามสถานะขนส่ง**
- ดึงสถานะจากขนส่ง (เก็บ, กำลังส่ง, ส่งถึง, ส่งไม่สำเร็จ)
- อัปเดตใน ERP อัตโนมัติ
- แจ้งเตือนเมื่อส่งไม่สำเร็จ

### ขนส่งที่รองรับในไทย

| ขนส่ง | รองรับ | จุดเด่น |
|-------|--------|---------|
| Kerry Express | ทุก Marketplace | เร็ว ครอบคลุม |
| Flash Express | ทุก Marketplace | ราคาถูก ครอบคลุม |
| Thailand Post | ทุก Marketplace | ครอบคลุมทุกจังหวัด |
| J&T Express | Shopee, TikTok | ราคาถูก |
| Ninja Van | Lazada, Shopee | ครอบคลุม |
| DHL | เฉพาะรายใหญ่ | ระดับสากล |

> 💡 **Tip:** การอัปเดต Tracking Number ช้าทำให้ Marketplace ปรับอันดับร้านค้าลด ถ้าอัปเดตช้าเกินกำหนด (Shopee 48 ชม., TikTok 72 ชม.) โดน Penalty Shipping Integration ช่วยอัปเดตทันที ไม่มีความเสี่ยง

## Customer Sync ซิงค์ข้อมูลลูกค้า

**Customer Sync** คือการดึงข้อมูลลูกค้าจาก Marketplace เข้าสู่ CRM อัตโนมัติ ทำให้ธุรกิจเก็บข้อมูลลูกค้าทุกคน แม้ซื้อผ่าน Marketplace

### วิธีการทำงาน

```
ลูกค้าซื้อบน Shopee
        │
        ▼
ERP ดึงออเดอร์ + ข้อมูลลูกค้า
        │
        ├── ชื่อลูกค้า (จากที่อยู่จัดส่ง)
        ├── เบอร์โทร
        ├── ที่อยู่
        ├── รายการสินค้าที่ซื้อ
        ├── ช่องทางที่ซื้อ (Shopee)
        └── วันที่ซื้อ
        │
        ▼
CRM บันทึกข้อมูลลูกค้า
        │
        ├── ถ้าลูกค้าใหม่ → สร้าง Profile
        ├── ถ้าลูกค้าเก่า → เพิ่มประวัติการซื้อ
        └── อัปเดต Segment (ลูกค้า VIP, ซื้อซ้ำ, ซื้อครั้งเดียว)
```

### ข้อมูลลูกค้าที่ซิงค์ได้

| ข้อมูล | ซิงค์ได้ไหม | หมายเหตุ |
|-------|------------|---------|
| ชื่อ-นามสกุล | ได้ | จากที่อยู่จัดส่ง |
| เบอร์โทร | ได้ | จากข้อมูลออเดอร์ |
| ที่อยู่ | ได้ | จากที่อยู่จัดส่ง |
| อีเมล | บาง Marketplace | Shopee ไม่ให้, Lazada ให้ |
| ประวัติการซื้อ | ได้ | จากออเดอร์ทั้งหมด |
| ช่องทางที่ซื้อ | ได้ | บันทึกไว้ใน CRM |
| ราคาที่ซื้อ | ได้ | จากยอดออเดอร์ |
| พฤติกรรมการดูสินค้า | ไม่ได้ | Marketplace ไม่เปิด |

### ประโยชน์ของ Customer Sync

**1. รู้ว่าลูกค้าคนไหนซื้อซ้ำ**

CRM บันทึกทุกการซื้อ ถ้าลูกค้าซื้อ 3 ครั้งใน 6 เดือน ระบบแท็กเป็น "ลูกค้าซื้อซ้ำ" ส่งโปรโมชั่นพิเศษได้

**2. รู้ว่าลูกค้าซื้อจากช่องทางไหน**

ลูกค้าคนเดียวซื้อบน Shopee 2 ครั้ง และ TikTok Shop 1 ครั้ง CRM บันทึกไว้ ธุรกิจรู้ว่าช่องทางไหนดีที่สุดสำหรับลูกค้าคนนี้

**3. ส่งโปรโมชั่นตรงกลุ่ม**

ลูกค้าที่ซื้อสินค้า A ส่งโปรสินค้า B ที่เกี่ยวข้อง ลูกค้าที่ไม่ได้ซื้อ 3 เดือน ส่งโปร "คุณไม่ได้มานาน"

**4. วิเคราะห์ Customer Lifetime Value**

รู้ว่าลูกค้าแต่ละคนซื้อรวมเท่าไรตลอดอายุการเป็นลูกค้า แยกลูกค้า VIP จากลูกค้าทั่วไป

> ⚠️ **Callout:** ข้อมูลลูกค้าจาก Marketplace มีข้อจำกัด เพราะ Marketplace เป็นเจ้าของข้อมูล ธุรกิจได้แค่ข้อมูลที่จำเป็นสำหรับการจัดส่ง นี่คือเหตุผลที่ควรกระตุ้นให้ลูกค้าซื้อผ่านช่องทางของธุรกิจโดยตรง (LINE OA, เว็บไซต์) เพื่อเก็บข้อมูลได้ครบ

## ตัวอย่างการใช้งานจริง

### ตัวอย่างที่ 1: ร้านเครื่องสำอาง — ออเดอร์ 800/วัน

ร้านเครื่องสำอางขายบน Shopee, TikTok Shop และ Lazada ออเดอร์รวม 800 ออเดอร์ต่อวัน ทีม 5 คน

**ก่อน Integration:**
- ทีม 5 คน ใช้เวลา 6 ชั่วโมง/วัน คีย์ออเดอร์จาก 3 Seller Center
- สต๊อกไม่ตรง 5-8 ครั้ง/สัปดาห์
- โดน Penalty จาก Shopee 3 ครั้ง/เดือน
- Tracking อัปเดตช้า บางครั้งเกิน 48 ชม.
- Rating 4.2

**หลัง Integration:**
- ออเดอร์ไหลเข้า ERP อัตโนมัติ ทีม 2 คนพอ
- สต๊อกซิงค์ Real-time ไม่มีการขายเกิน
- ไม่โดน Penalty เลย
- Tracking อัปเดตทันที ไม่เกิน 1 ชม.
- Rating เพิ่มเป็น 4.8
- ยอดขายเพิ่ม 30% เพราะอันดับร้านค้าดีขึ้น

### ตัวอย่างที่ 2: ผู้กระจายสินค้า — 3 คลัง 3 ช่องทาง

ผู้กระจายสินค้ามีคลัง 3 แห่ง ขายบน Shopee, TikTok Shop, Lazada และขายส่ง B2B

**ก่อน Integration:**
- สต๊อก 3 คลังแยกกัน ไม่รู้สต๊อกรวม
- จัดส่งจากคลังผิด บางครั้งส่งจากไกล ค่าขนส่งสูง
- ขายส่งและออนไลน์สต๊อกทับกัน

**หลัง Integration:**
- สต๊อก 3 คลังรวมใน ERP รู้สต๊อกรวม Real-time
- ระบบเลือกจัดส่งจากคลังที่ใกล้ลูกค้าที่สุด
- ค่าขนส่งลด 25%
- ความเร็วจัดส่งเพิ่ม 40%
- สต๊อกขายส่งและออนไลน์แยกกัน ไม่ทับกัน

### ตัวอย่างที่ 3: ร้านอาหารแห้ง — หน้าร้าน + ออนไลน์

ร้านอาหารแห้งมีหน้าร้าน 1 สาขา ขายออนไลน์บน Shopee และ TikTok Shop

**ก่อน Integration:**
- สต๊อกหน้าร้านใช้สมุด ออนไลน์ใช้ Excel
- ขายออนไลน์แล้วของหมดที่หน้าร้าน ต้องยกเลิก
- ลูกค้าออนไลน์ไม่รู้ว่ามีหน้าร้าน

**หลัง Integration:**
- POS หน้าร้านเชื่อมกับ ERP สต๊อกลดทุกช่องทาง
- ขายที่ไหนสต๊อกลดทุกที่ ไม่มีทับกัน
- ข้อมูลลูกค้าออนไลน์เข้า CRM ส่งโปร "มาซื้อที่หน้าร้านรับส่วนลด"
- ยอดขายหน้าร้านเพิ่ม 20% จากลูกค้าออนไลน์ที่มาซื้อที่ร้าน

> 💡 **Tip:** การวัดผลหลังติดตั้ง Integration ควรทำหลัง 1 เดือน เพื่อให้ทีมเริ่มคุ้นกับระบบ วัด KPI เช่น เวลาจัดการออเดอร์ ความผิดพลาดสต๊อก Rating และยอดขาย เปรียบเทียบก่อนและหลัง

## คำถามที่พบบ่อย

### 1. Marketplace Integration คืออะไร

Marketplace Integration คือการเชื่อมต่อ Marketplace (Shopee, TikTok Shop, Lazada) เข้ากับ ERP ผ่าน API เพื่อดึงออเดอร์ ซิงค์สต๊อก อัปเดต Tracking และซิงค์ข้อมูลลูกค้าอัตโนมัติ โดยไม่ต้องเข้า Seller Center แต่ละช่องทาง

### 2. ต้องเข้า Seller Center อีกไหมหลังมี Integration

ส่วนใหญ่ไม่ต้อง ระบบจัดการออเดอร์ สต๊อก ใบปะหน้า และ Tracking ได้จาก ERP แต่บางกรณี เช่น แชทกับลูกค้า จัดการคำสั่งซื้อที่มีปัญหา หรือตั้งค่าโปรโมชั่น อาจต้องเข้า Seller Center

### 3. Order Sync แบบ Real-time ทำงานอย่างไร

เมื่อลูกค้าสั่งซื้อบน Marketplace จะส่ง Webhook ไป ERP ทันที ERP ดึงรายละเอียดออเดอร์ผ่าน API ภายใน 2-5 วินาที ทีมคลังเห็นออเดอร์ใน ERP ทันที

### 4. Inventory Sync ป้องกันการขายเกินสต๊อกอย่างไร

เมื่อมีออเดอร์ในช่องทางหนึ่ง ERP ลดสต๊อกและส่ง API ไปอัปเดตสต๊อกในทุกช่องทางทันที ภายใน 2-5 วินาที ทุกช่องทางเห็นสต๊อกที่ลดลงแล้ว ป้องกันการขายเกิน

### 5. Webhook ต่างจาก Polling อย่างไร

Webhook คือ Marketplace ส่งข้อมูลไป ERP ทันทีเมื่อมี Event (Real-time) Polling คือ ERP ดึงข้อมูลจาก Marketplace ทุก 5-15 นาที Webhook เร็วกว่าแต่ต้องมี Server รับ ที่ดีควรใช้ทั้งสองแบบ

### 6. Buffer Stock คืออะไร ทำไมต้องมี

Buffer Stock คือสต๊อกที่เก็บไว้ไม่ขาย เพื่อป้องกันการขายเกินจากความหน่วงของ API ถ้าสต๊อกจริง 10 ชิ้น ตั้ง Buffer 2 ชิ้น Marketplace แสดง 8 ชิ้น เผื่อกรณีมีออเดอร์พร้อมกันในช่วงที่ API ยังไม่ซิงค์

### 7. ระบบรองรับขนส่งอะไรบ้าง

ระบบที่ดีรองรับ Kerry Express, Flash Express, Thailand Post, J&T Express และ Ninja Van สำหรับ Marketplace ในไทย สามารถพิมพ์ใบปะหน้าและอัปเดต Tracking อัตโนมัติ

### 8. ข้อมูลลูกค้าจาก Marketplace ครบไหม

ได้ข้อมูลพื้นฐาน เช่น ชื่อ เบอร์โทร ที่อยู่ และประวัติการซื้อ แต่ไม่ได้ข้อมูลเชิงลึก เช่น พฤติกรรมการดูสินค้า หรืออีเมล (บาง Marketplace) เพราะ Marketplace เป็นเจ้าของข้อมูล

### 9. ใช้เวลาติดตั้งนานเท่าไร

ถ้าใช้ Business Automation Platform ที่มี Marketplace Integration พร้อม ติดตั้ง 1-3 วัน ถ้าพัฒนาเอง อาจใช้ 1-3 เดือน ขึ้นอยู่กับความซับซ้อน

### 10. ถ้า API ของ Marketplace เปลี่ยน ทำอย่างไร

Marketplace ปรับ API เป็นระยะ ระบบที่ดีต้องมีทีมงานติดตามและอัปเดต API ให้ Business Automation Platform ที่มีซัพพอร์ตจะจัดการให้ ไม่ต้องกังวล

## CBoom ช่วยเรื่อง Marketplace Integration ได้อย่างไร

CBoom มีโมดูล **CBoom Marketplace** ที่เชื่อมต่อ Shopee, TikTok Shop และ Lazada เข้ากับระบบ CBoom ผ่าน Official API ครบทุกฟังก์ชันที่กล่าวถึงในบทความนี้

### ฟังก์ชันที่ CBoom มี

**Order Sync**
- ดึงออเดอร์จาก Shopee, TikTok Shop, Lazada ผ่าน Webhook (Real-time)
- มี Polling สำรองทุก 5 นาที ป้องกันออเดอร์หาย
- ออเดอร์ทุกช่องทางในหน้าจอเดียว

**Inventory Sync**
- ซิงค์สต๊อกข้ามช่องทาง Real-time
- รองรับ Buffer Stock
- แจ้งเตือนเมื่อสต๊อกต่ำ

**Shipping Integration**
- พิมพ์ใบปะหน้าจากในระบบ
- รองรับ Kerry, Flash, Thailand Post, J&T, Ninja Van
- อัปเดต Tracking Number กลับ Marketplace อัตโนมัติ

**Customer Sync**
- ข้อมูลลูกค้าจาก Marketplace เข้า CBoom CRM อัตโนมัติ
- บันทึกประวัติการซื้อทุกช่องทาง
- แยกลูกค้าตาม Segment

### ทำงานร่วมกับโมดูลอื่น

- **CBoom Warehouse** — สต๊อกซิงค์กับ Marketplace Real-time จัดการหลายคลัง ([ดูรายละเอียด](/inventory/))
- **CBoom CRM** — ข้อมูลลูกค้าเข้า CRM ทีมขายเห็นประวัติทุกช่องทาง ([ดูรายละเอียด](/crm/))
- **CBoom POS** — สต๊อกหน้าร้านและออนไลน์เชื่อมกัน ([ดูรายละเอียด](/pos/))
- **CBoom AI** — วิเคราะห์ยอดขายข้ามช่องทาง แนะนำการเติมสต๊อก ([ดูรายละเอียด](/ai/))
- **Dashboard** — ยอดขายรวมทุกช่องทาง Real-time

> 💡 **Tip:** CBoom ใช้ Official API ของทุก Marketplace ปลอดภัย ไม่ถูกแบน และทีมงานติดตาม API Changes ให้ ไม่ต้องกังวลเรื่อง API เปลี่ยน

## สรุป

Marketplace Integration คือหัวใจของการขายออนไลน์ในยุคที่ลูกค้าช้อนข้ามช่องทาง การคีย์มือไม่ Scale ได้อีก ระบบที่ดีต้องมี:

- **Order Sync** — ดึงออเดอร์ Real-time ผ่าน Webhook
- **Inventory Sync** — ซิงค์สต๊อกข้ามช่องทาง ป้องกันขายเกิน
- **Webhook** — รับข้อมูลทันที ไม่ต้องรอ
- **Shipping Integration** — พิมพ์ใบปะหน้าและอัปเดต Tracking อัตโนมัติ
- **Customer Sync** — ข้อมูลลูกค้าเข้า CRM

ผลลัพธ์ที่ธุรกิจได้รับ:
- ลดเวลาจัดการออเดอร์ 85%
- ลดความผิดพลาด 95%
- เพิ่มความเร็วจัดส่ง 40%
- Rating ดีขึ้น อันดับร้านค้าดีขึ้น
- ยอดขายเพิ่ม 20-30%

CBoom มี Marketplace Integration ครบทุกฟังก์ชัน ใช้ Official API ปลอดภัย ทีมงานคนไทยดูแล ทดลองใช้ฟรี ไม่ต้องใช้บัตรเครดิต
